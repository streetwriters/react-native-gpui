# Changelog

All notable changes to `@react-native-gpui/core` are listed here. Each version's section becomes the notes of its GitHub release.

## Unreleased

- Builds against gpui-fast `11fd570`: on Linux, windows report themselves active while the test driver runs the app, so focus and blur reach the elements of a test window, as on macOS; on Windows, a test run's window scale factor (`RN_GPUI_TEST_SCALE_FACTOR`) applies, as on macOS and Linux.
- `RN_GPUI_TEST_SCALE_FACTOR` is honoured on Linux too: the runtime hands it to the X11 backend as `GPUI_X11_SCALE_FACTOR` before the platform starts, so a test run gets the same 2x display it gets on macOS.
- The test driver's `windowReveal` reports an alpha of 1 on platforms without a reveal alpha, instead of `null`.
- A native slot corrects for the offset of the window's frame (the menu bar and the frame a Linux window draws), so its React Native content is placed and hit where the slot is.
- On Linux a window's `isMaximized` reads the window manager's state, which it always reported as false.
- A mount update that changes nothing the runtime draws (no props, frame, text or host component change) no longer notifies its view. Fabric sends such updates for every ancestor of a node whose content overflows its parent, and each one rebuilt the whole screen under it on every commit.
- The test driver's idle check waits for a window size that has not reached React yet, so a test that resizes a window and waits for idle sees the new layout.

- The runtime builds on Linux and Windows again: the header the Rust bridge compiles no longer includes curl, whose headers only the C++ build has.
- Every module moved to react-native-gpui-modules, with its documentation, fixtures and tests: `fonts`, `fs`, `gesture-handler`, `reanimated`, `safe-area-context`, `screens`, `svg`, `vector-icons` and `worklets`, and the desktop-only `image-manipulator`, `notifications`, `pdf`, `secure-storage` (now part of `keychain`), `spellcheck`, `system`, `updater` and `webauthn`. This repository has the runtime and its tools only; the tester covers the runtime without any module.
- Escape cancels a view drag: the target gets `onDragLeave`, nothing drops and `onDragEnd` reports `dropped: false`.
- Views can be dragged to other views in the app. `draggable` views start a drag when a press moves 4 points, with `onDragStart`, `onDrag` and `onDragEnd`; `droppable` views get `onDragEnter`, `onDragOver`, `onDragLeave` and `onDrop` and take `dragOverStyle`. The drag follows the pointer out of the source. `DragDrop` (`setPayload`, `getPayload`, `getState`, `onMove`), `useDragState`, `useIsDragging`, `DragPreview` and `useDragAutoScroll` are exported from `@react-native-gpui/core/desktop`. Needs a prebuilt runtime built with the change.
- A one-line `Text` cut short with an ellipsis is as wide as the width it was given, as a block with `text-overflow: ellipsis` is, instead of as wide as the text that was left. A line is as tall as the tallest font it uses, fallback fonts such as Hiragino included, as in a browser; a color emoji font is left out, as there.
- A nested `Text` with a `backgroundColor` is painted behind its words: a rectangle over the font's content area, as a browser paints an inline span's background (a line that wraps keeps a whole-line-tall rectangle).
- While the test driver is on, windows report themselves active to the UI toolkit, so focus and blur events reach text inputs in a background run. `RN_GPUI_TEST_SCALE_FACTOR` makes a window lay out and draw at that scale whichever display it is on. Both need the gpui-fast revision that carries them.
- A background run opens its windows on the secondary display when there is one (`launchApp` passes `main` until the scale override is in the runtime), and `RN_GPUI_TEST_DISPLAY` (`main`, `secondary` or an index) chooses the display. A display that does not exist falls back to the main one with a log line. The test driver has a `displays` command.
- `Network.setDnsOverHttps()` takes a list of DNS-over-HTTPS servers. A name a server cannot resolve is asked of the next one and then of the system resolver, and `getSettings()` also reports `dnsOverHttpsServers`.
- An app launched with the argument `--hidden` opens its main window without showing it or taking focus, for an app that starts at login in the background behind a tray icon.
- Added `Network.setProxy()`, `setDnsOverHttps()`, `getSettings()` and `proxyForUrl()` to set the proxy (a proxy URL, Chromium proxy rules and a bypass list, `'direct'` or the system's) and a DNS-over-HTTPS server of the HTTP client that `fetch`, `XMLHttpRequest` and remote image and font loads share. On macOS requests follow the system proxy settings by default. WebSocket connections are not covered yet. Needs a prebuilt runtime built with the change.
- `extensions::rendering_node()` returns a `NodeHandle` for the node whose component renderer is running, and `NodeHandle::notify(cx)` builds and paints that node again. A renderer that rasterises or loads something in the background uses it to show the result when it is ready, which it could not do before: a render has no way to reach back into its node.
- `rngpui::createTurboModule(name, jsInvoker)` (in `GpuiModules.h`) makes a TurboModule the way the main runtime does, for the invoker it is given: the app's C++ provider, then the extension providers (Rust modules), then core's own. A library that runs another JavaScript runtime, such as a worker, uses it to give that runtime the app's native modules.
- On macOS the scroll bar follows the system's scroller style: with legacy scrollers (System Settings "Show scroll bars: Always", or Automatically while a mouse is connected) it is always shown on a track, and the app follows the setting as it changes. Overlay scrollers keep the auto-hide behaviour. `RN_GPUI_SCROLLER_STYLE=legacy|overlay` forces it on any platform. The bar overlays the content rather than taking layout width. Needs a prebuilt runtime built with the change.
- On macOS the scroll bar follows the system's scroller style: with legacy scrollers (System Settings "Show scroll bars: Always", or Automatically while a mouse is connected) it is always shown on a track, and the app follows the setting as it changes. Overlay scrollers keep the auto-hide behaviour. `RN_GPUI_SCROLLER_STYLE=legacy|overlay` forces it on any platform. With legacy scrollers the bar also takes 12 points (or the thickness of a `ScrollBar` child that sets one) from the scroll view's content on its scroll axis, as classic scroll bars do in AppKit and Chromium, and the layout follows the setting as it changes. Needs a prebuilt runtime built with the change.
- The scroll indicator no longer shows for a scroll the app asked for with `scrollTo` or `scrollToEnd`, which moves the content without showing the thumb, as a script's scroll does under a browser's overlay scrollbars. A sidebar scrolled to its selected item when it opened used to show a thumb until it timed out. `flashScrollIndicators()` now shows the thumb for its delay; it did nothing. Needs a prebuilt runtime built with the change.
- A React commit while the pointer rests inside the window no longer rebuilds every view. Typing in a field with the mouse over the window rebuilt the whole tree about 30 times per key: each mount batch asked for a window refresh to re-work hover, and the hover pass dispatched a synthetic mouse move that flipped GPUI's input modality from keyboard to mouse, which refreshes the window again on the next key. The hover pass now follows the pointer without a window refresh, and after keyboard input it finds the view under the pointer from the node frames, in paint order, so an absolute overlay over a row keeps the hover, instead of sending a mouse move, so the modality stays. Needs a prebuilt runtime built with the change.
- `buttons` on the pointer events is the mask of the mouse buttons actually held, as on the web: 1 left, 2 right, 4 middle, combined when several are held, and 0 when none is. A move while a button was held reported 0, so a handler that tests the held button to tell a drag from a hover saw no drag. `onPointerMove` now also fires for a move with nothing held, and a right or middle button drag reports its moves, and its release `onPointerUp`, to the view it started on; the release was not reported at all. Needs a prebuilt runtime built with the change. The window losing activation now ends every held press with `onPointerCancel` and clears the mask, as in a browser.
- `View` takes `onWheel` and `onWheelCapture`, the web's wheel event for the mouse wheel and the trackpad: `deltaX`, `deltaY` and `deltaZ` with the web's signs, `deltaMode` (pixels at full precision for a trackpad, lines for a mouse wheel), `isTrackpad`, `phase` and `momentum` for a trackpad gesture, the modifier keys, the pointer position and `timestamp`. A trackpad pinch arrives as a wheel event with `ctrlKey` and the zoom in `deltaY`, and shift with a mouse wheel gives `deltaX`, as in a browser. The event bubbles; `preventDefault()` or `stopPropagation()` keeps a parent `ScrollView` from scrolling, and a view with no wheel handler on its path scrolls at once. Events are delivered in order and none is dropped. Needs a prebuilt runtime built with the change.
- The keyboard focus ring of a focusable view follows its `borderRadius`, as Chromium's does. Needs a prebuilt runtime built with the change.
- A solid `outline` follows the view's `borderRadius`, as CSS does: the ring is rounded, with the border radius plus `outlineOffset` as its inner radius, and a corner with no radius stays square. The square ring also had a notch in each outer corner, now filled. Needs a prebuilt runtime built with the change.
- A single-line `TextInput` is as tall as a line of `Text` in the same font and size, as a browser input is: its content height is measured from its text, its placeholder or, when both are empty, its font, instead of being forced to 1.4 times the font size. An input with no `lineHeight` at 15 px is now 17.5 px of content at 2x instead of 21. A multiline input keeps its minimum height. Needs a prebuilt runtime built with the change.
- `window.visible: false` in `desktop.json` (and `DesktopAppConfig::visible(false)`) starts the main window hidden, as the `--hidden` argument does: it is created at its restored size and position, the app mounts and renders in it, and it is not shown, focused or activated until `DesktopWindow.show()`. A window that was hidden reports `isVisible: false` from the start, and is shown clear and made opaque once the frames after the show have been drawn (at most 80 ms later). Needs a prebuilt runtime built with the change, and a CLI with the new schema key.
- A press on a draggable view that is released before it moved far enough to become a drag now gives the touch its end, so a `Pressable` on a draggable view fires `onPress`. The release was dropped.
- A shortcut with no scope now takes a key from a menu accelerator on the same keys, as `docs/desktop-keyboard-shortcuts.md` orders them. The default menu's Close (`mod+w`) closed the window even when the app registered `mod+w`, because only scoped shortcuts were counted, a menu binding added later won a tie in the keymap, and with nothing focused the shortcut had no dispatch path. Needs a prebuilt runtime built with the change.
- A press now ends when the button is released outside the window, and the moves outside it reach the pressed view, as `docs/view.md` says: the root's pointer listeners only ran while the pointer was over the window, so a release outside left the gesture active and the app never became idle. Needs a prebuilt runtime built with the change.
- `RN_GPUI_TEST_DISPLAY=retina` opens a test window on the display with the highest scale factor, if it is at least 2, so a test that depends on the display's own scale does not depend on which display is main. `app.displays()` reports each display's `scaleFactor`.
- Dragging a scroll bar thumb no longer fails with "Unsupported top level event type topScrollBarDrag" when the scroll view has no `ScrollBar` child. `ScrollView`, and so `FlatList`, `SectionList` and `VirtualizedList`, take `onScrollBarDragStart`, `onScrollBarDrag` and `onScrollBarDragEnd`, which report the thumb drags with the scroll offset. The `ScrollBar` component's `onDrag*` props work as before. Needs a prebuilt runtime built with the change.
- `experimental_LayoutConformance` works on desktop: its component is registered, so a `strict` subtree gets Yoga's errata cleared. Desktop adds a Yoga errata, `FlexBasisAsIntrinsicSize`, that `strict` clears: a flex item that can grow and has a basis of zero or a percentage, as CSS gives `flex: 1`, is measured as content while its container is sized from its content, so a row item with a `flex: 1` inner row is as wide as its content instead of collapsing. The default conformance is unchanged. Copies of Yoga's `CalculateLayout.cpp`, `YGEnums` and `Errata.h` in `ReactCommonOverrides` carry it (see its README). Needs a prebuilt runtime built with the change.
- The test driver no longer scans every node after each draw for running transitions; it follows only the nodes a transition was started on, which shortens each draw by about a millisecond on a large tree.
- `XMLHttpRequest` (and so `fetch`) response headers are an object of names and values, as React Native's are: `getAllResponseHeaders()` returned `0: etag,"..."` lines, so `getResponseHeader('ETag')` was `null`. Headers a server sends more than once are joined with `, `. Needs a prebuilt runtime built with the change.
- Each instance of a native tree is in an element id scope of its own, so two components that use the same GPUI element id for their state (a `div().id("button")` in every button) no longer share it. A state update inside a native tree (a `setState` in one of its components) now sends its changes to the runtime; only the commits `NativeRoot` itself started did. Fast Refresh reaches components inside a native tree in development, with their state kept.
- A native component can tell JavaScript when the pointer enters or leaves it, and a native tree inside a React Native view is clipped by its rounded `overflow: hidden`, moved by its transforms, covered by React Native views over it and scrolled with the content around it; the tester's `mixed-matrix` test checks each, and `docs/mixed-views.md` is its support table.
- The test driver sees the instances of a native tree: `tree()` nests them under the node that shows them, `query` and the locators find them by `testID`, `text`, `role` and `label` and give them frames, and `click` and `hover` through a locator reach them. An instance with an `accessibilityRole` prop is in the accessibility tree with its `accessibilityLabel` and `testID`. The trees of nodes that are gone are dropped when a new one starts, and one shared reconciler registers with React's developer tools so Fast Refresh reaches components inside a tree. Needs a prebuilt runtime built with the change.
- `hostCounters()` of the testing client also reports `nativeOpsApplied`, `nativeApplyMicros` and `nativeRenderMicros`, for measuring native trees. One commit that changes the text of a thousand instances is a batch of 1,000 operations (44 KB of JSON), takes 3 to 5 ms in the reconciler, 0.15 ms to apply and 0.33 ms to build the elements.
- `NativeRoot` (from `@react-native-gpui/core/desktop`) renders React elements whose types name native components into a native tree with a second React reconciler (`react-reconciler` 0.33.0, with `its-fine` carrying the outer contexts in), one batch of operations per commit, handlers kept in JavaScript and called by events that name the instance, and render errors thrown again in the outer tree. Needs a prebuilt runtime built with the change.
- `NativeSlot` (from `@react-native-gpui/core/desktop`) puts React Native children inside a native tree. They are as wide as the tree's layout makes the slot and as high as their content (the components after the slot move with it), they are painted, clipped and hit where the slot is, `measure` and the test driver report their true place, and they see the contexts of the native tree as well as those of the `NativeRoot`. A `NativeRoot` can be nested in a slot. Needs a prebuilt runtime built with the change.
- `NativeSlot` takes a `fill` prop: the slot then has the height its native parent's layout gives it (a dialog, a tab, a panel of a fixed height) and its content is laid out in that, so a `ScrollView` or a list in it scrolls. Without it the slot is as high as its content and is clipped where the layout makes it shorter.
- `NativeVirtualList` (from `@react-native-gpui/core/desktop`) is a virtual list for native trees: it scrolls natively, reports the range in view, and only those items and a few more on each side exist. Items are as high as their content (native items measured by GPUI, items with a `NativeSlot` by their React Native content; unmeasured ones count as `estimatedItemHeight`), the scroll position moves with an item above the viewport that changes size so nothing jumps, and the ref has `scrollToIndex({ index, align })` (start, center or end) and `scrollToOffset`. `onEndReached` fires once when the end comes within `endReachedThreshold`. Items are keyed by `keyExtractor` and keep their React state; `recycleItems` keys them by position in the window instead, reusing their React state, for stateless rows only. Needs a prebuilt runtime built with the change.
- A native component can be reused: `NativeComponent::recyclable` and `recycle` let the tree keep the component of a removed instance in a pool of its type and hand it to the next instance of the type, so removing and creating items while scrolling does not build components. `hostCounters()` reports `nativeInstancesCreated` and `nativeInstancesRecycled`.
- Focus and keys work across the edge of a native tree. Tab and Shift+Tab move through a native tree in document order, entering and leaving the React Native content of its slots (a native tree is a tab group at the position of its `NativeRoot`, and React Native nodes inside a slot are ordered by position instead of by tag); a key the React Native content of a slot does not handle reaches the native components that contain the slot.
- A `NativeSlot` shows its content only once the content has the width the native layout gave the slot, so a slot in a popover or any freshly shown place never paints or takes presses at a wrong size. The test driver's idle check waits for slots that are still getting their width.
- An image prop of a component in a native tree takes what React Native accepts, as the view config the spec generated says it does: a `require()`d asset, a uri string, an object with `uri` or an array of sources, resolved with `Image.resolveAssetSource` before it reaches the runtime.
- The `Commands` of a spec work on a ref to a native tree instance as they do on a Fabric ref: `dispatchCommand` of the renderer proxy sends a command to the instance when the ref is one.
- A native tree instance can be sent a command: `NativeComponent::command` and the `command` operation, and the refs a `NativeRoot` gives for its instances have `command(name, ...args)`. A component that a spec generated (the same one a Fabric node runs) is registered for a native tree with `<Spec>Component::<T>::register_native_tree()`.
- Overlays work across the boundary: React Native content in a slot inside a native popover (a deferred panel) is over the other content and takes presses, and a native tree inside a React Native `Modal` takes presses.
- The test driver's `type` also types into the instances of a native tree, and the testing client has `compose(tag, steps)` to run an input method's steps (`{ mark }`, `{ commit }`) on a text input.
- `react_native_gpui::native_tree` holds native trees: instances of components created and updated by batches of operations (create, append, insert, remove, update), moved by keyed reorders, dropped with their subtrees, telling JavaScript through events that name the instance, and rendered as one GPUI element tree by the components that place their children. Needs a prebuilt runtime built with the change.
- The `rn-gpui-sys` build script tracks every C++ input: all of `ReactCxxPlatform`, the sources and include directories the app contributes (the host component glue autolink generates among them) and the headers React Native's codegen makes for the app's specs. Editing any of them is picked up by the next build; a changed host component spec configures CMake again, which fixed the link failure on `_props_*` symbols after a props-only change.
- A `measured` host component can implement `Spec::measure(props, constraint)`, which Yoga calls on the layout thread with the minimum and maximum size it offers, and `host_component::measure_text` sets text in a font under a width for it. The size is right in the first layout pass, where `set_intrinsic_size` arrives a commit later. Needs a prebuilt runtime built with the change.
- A press, release and click on a React child inside a `container` host component now also reach the component's own GPUI element, so its pressed and hover states work over its children. The press stopped at the child. Needs a prebuilt runtime built with the change.
- A host component command runs in the window of the view it was sent to, and the generated context has `window()` for it and `with_window(f)` for `create` and `update`, which run in a mount batch with no window of their own. Commands used the main window before. Needs a prebuilt runtime built with the change.
- Host components can reach GPUI's `App`: the generated context has `app()`, which returns the `App` of the mount, frame or command that called the component, for creating entities, subscribing and reading globals. Needs a prebuilt runtime built with the change.
- `register_app_init` and `register_root_wrapper` (re-exported from `react_native_gpui`) let a module run code once before the first window opens and wrap the root view of every window that hosts a React tree. Without a registration nothing changes. Needs a prebuilt runtime built with the change.
- A horizontal `ScrollView` scrolls with the wheel: the desktop view config did not pass its `horizontal` prop to the native side, so every scroll view scrolled only vertically. A sideways trackpad swipe and shift with a vertical wheel move a horizontal one; a vertical wheel alone no longer scrolls it sideways, and a sideways swipe no longer scrolls a vertical one, so a vertical scroll view inside a horizontal one routes each axis to the right view. `pagingEnabled` and the snap props work on the horizontal axis. Needs a prebuilt runtime built with the change.
- `experimental_backgroundImage` and `backgroundImage` also draw `repeating-linear-gradient()` and `repeating-radial-gradient()`: the stops from the first to the last repeat along the line or out from the centre, alone or among plain gradient layers. React Native's parser does not read them; desktop marks the layer in its view config and the renderer repeats the stops. Needs a prebuilt runtime built with the change.
- A menu drawn by the app (`ContextMenu.show` with `presentation: 'custom'`) is at most 80% of the window's height and scrolls when it has more rows than fit; the keyboard keeps the highlighted row in view and a submenu stays anchored to its row while the list is scrolled. Needs a bundle built with the change.
- Menu role `pasteWithoutFormatting` pastes the clipboard as plain text into the focused text input, with `mod+shift+v` as its accelerator. `Menu.performRole()` acts on the main window when no window is active, as when the app is in the background. Needs a prebuilt runtime built with the change.
- `App.beep()` plays the system alert sound. Needs a prebuilt runtime built with the change.
- `Tray.onClick(handler)` reports a click on the tray icon with its button and whether it is a double click. Needs a prebuilt runtime built with the change.
- `View` takes a `tooltip` string, shown after the pointer rests over the view as the web's `title` is. macOS uses the system tooltip; Windows and Linux draw one in the window for now (`RN_GPUI_TOOLTIP=drawn` forces that on macOS). It is placed with the window's zoom factor, follows a change of the text, hides on leave, press and window deactivation, and is the view's accessibility description. Needs a prebuilt runtime built with the change.
- `Menu.setDockMenu(items)` sets the menu of the Dock icon on macOS, with `onPress` per item. Needs a prebuilt runtime built with the change.
- Menu roles `zoomIn`, `zoomOut` and `resetZoom` step the focused window's zoom factor through a browser's levels and back to 100%, from the application menu or `Menu.performRole()`. Needs a prebuilt runtime built with the change.
- `App` (from `@react-native-gpui/core/desktop`): `launchArgs()`, `quit()`, `exit(code)`, `relaunch()` and `onSecondInstance(handler)`. With `singleInstance`, a second launch now shows the main window (restoring a minimized or hidden one) as well as focusing it, and its arguments reach JS. Needs a prebuilt runtime built with the change.

- Background mode: with the test driver on, or `RN_GPUI_BACKGROUND=1`, the app never activates itself, runs as an accessory application on macOS (no Dock icon or bounce, the menu bar stays the user's), opens its windows without focus and shows them behind the other windows, and `window.show()` and `window.focus()` stay behind and logical. `RN_GPUI_BACKGROUND=0` turns it off. - `ref.focus()` and `ref.blur()` on a `focusable` View move focus as `HTMLElement.focus()` and `blur()` do: the previously focused view loses its `focusStyle` and the new one gains it, and an `onFocus`/`onBlur` handler runs. Needs a prebuilt runtime built with the change.
- A text's height is rounded to the nearest device pixel rather than up, as Chromium snaps a block of lines: three lines of `lineHeight: 19.2` are 57.5 points tall at a scale of 2 (they were 58), two lines 38.5.
- The window options in `desktop/desktop.json` (`window.titleBar`, `trafficLightPosition`, `background`, `windowButtons`, `shadow`, `resizable`, `width`, `height`, `title` and the others, plus `accessory`) reach the app on every build instead of only when `init-desktop` regenerates `main.rs`. `DesktopAppConfig::from_env_with_defaults` applies them, and a builder call made after it still wins. Needs the CLI that records them.
- Text line boxes are rounded at the device scale, as Chromium lays text out in device pixels: a line without an explicit `lineHeight` is the ascent and descent each rounded to whole device pixels, so Inter at 13 points is 15.5 points tall at a scale of 2, not 16, and the baseline half leading is rounded down to a device pixel. Text measures already on the 1/scale grid, so Yoga's ceil no longer adds a pixel to every line.
- Text weighs what Chromium's does on macOS: glyph coverage follows Skia's luminance-dependent curve in place of Core Graphics' font smoothing. Light text on a dark background was about 7 to 10% lighter than Chromium's and regular dark text about 2% lighter; both are now within 1%, and the pixels that differ visibly fall from several percent to under one percent. Needs the gpui-fast revision that carries the change.
- A view inside a parent that has a border is painted where its layout frame puts it. It was drawn one border width up and to the left of its frame (2 points for a `borderLeftWidth` of 2), so everything inside a bordered list row was off by the border, and a press landed beside what was drawn.
- Text sits on the baseline a browser gives it: the line's ascent and descent are each rounded to whole points and the half leading is rounded down, where gpui centred the unrounded font metrics. Inter at 13 points was drawn one device pixel (half a point) higher at a scale of 2, which made most small text differ from Chromium's pixels; the glyph shapes and subpixel positions already matched.
- Clicking a view no longer focuses a `Text` or other node that only exists for accessibility: the press focuses the nearest `focusable` view. The accessibility-only focus was dropped as soon as that node was updated, which blurred the window and left a focusable ancestor's `onKeyDown` without events after a subtree had been hidden and shown again (`Activity`, react-freeze).
- A `boxShadow` blur is as wide as in CSS: its gaussian has a standard deviation of half the blur radius. The blur radius was used as the standard deviation, which made every blurred shadow twice as wide and darker at the edge.
- `hitSlop` now also extends hover and pointer moves (`onPointerEnter`, `onPointerLeave`, `onPointerMove`) and the view's `cursor`, not just presses, so a thin divider can be painted at 1 point and show `col-resize` over a wider grab area. `hoverStyle` still follows the painted box.
- A text is measured to the pixel and not rounded up to a whole point first, so its frame is Yoga's ceil to the device pixel grid (at a scale of 2 a text 39.16 points wide has a frame 39.5 wide, not 40). A line without an explicit `lineHeight` is as tall as its ascent and descent each rounded to a whole point, as in a browser: Inter at 13 and 15 points is 16 and 19 tall.
- A view that clips to its rounded corners (`borderRadius` with `overflow: 'hidden'`) now clips to the corners as drawn when it has a `transform`: the clip was left at its untransformed size and position, so a scaled view was cut to the unscaled shape. A rotation clips to the rotated view's bounding box. Needs the gpui-fast revision that carries the change.
- `RN_GPUI_DEBUG_JS_TASKS=1` makes the test driver's idle error list the JavaScript tasks that are queued or running, each with its age and the call stack that queued it.
- A one-line text with `numberOfLines` is no longer cut short with an ellipsis when it fits the box it was measured into within the pixel rounding of that box.
- A key press goes to the focused view once and bubbles through React, instead of being sent once for every focusable view on the path to it, so an `onKeyDown` on a list no longer runs two or three times per press.
- The `nativeEvent` of a press (`onPress`, the responder events) has `shiftKey`, `ctrlKey`, `altKey` and `metaKey`, as the pointer events do.
- `DesktopWindow.show()` brings back a window that was minimized, and neither it nor `hide()` logs `RefCell already borrowed` errors from GPUI's window code any more: the operating system's own window call now runs after the update that asked for it, since it reports the change while it makes it.
- State styles can change `outlineColor`, `outlineWidth` and `outlineOffset`, for example to draw a keyboard focus ring.
- A native-driven or Reanimated animation of `backgroundColor` or `color` now paints: colors that arrive as negative 32-bit integers, which is every color with a high alpha byte from Reanimated, were converted to unsigned through a double and came out transparent.
- Files dragged in from the operating system: `View` takes `acceptsFiles`, `onDragEnter`, `onDragOver`, `onDragLeave` and `onDrop` events carrying each file's path, name, size, media type and the pointer position, and a `dragOverStyle` state style. Needs a prebuilt runtime built with the change.
- Menu items take an `onPress` handler, run when the item is chosen in a context menu (`ContextMenu.show`, `ContextMenuView`) or in the application menu, alongside the id the menu already reports.
- What the pointer is over is worked out again after a mount batch, as a browser does after a layout: a view that mounts under a still pointer receives `onPointerEnter`, without the pointer moving.
- Added `DesktopWindow.setZoomFactor()` and `getZoomFactor()` to scale a window's content (0.25 to 5), `getTitle()`, and `isVisible`, `title` and `zoomFactor` in the window state. `stateChange` events now also report `isVisible`, `title` and `zoomFactor` changes. Needs a prebuilt runtime built with the change.
- Added `DesktopWindow.setBackgroundColor()` and `setChromeAppearance()` to color a window's background and give its native title bar a light or dark look. macOS only for now.
- Added state style props on every `View`: `hoverStyle`, `activeStyle`, `focusStyle`, `focusVisibleStyle`, `group`, `groupHoverStyle` and `groupActiveStyle`. A hover or press repaints in native code, without a round trip to JavaScript and without React rendering. They can change `backgroundColor`, `opacity`, `boxShadow`, border colors, `transform` and the `color` of the text inside, and a property that a native-driven animation is animating keeps its animated value. Needs a prebuilt runtime built with the change.
- Resizing a window continuously no longer crashes a large app with "Maximum update depth exceeded". `useWindowDimensions` in the main window no longer re-renders on every frame of a move or resize, `SafeAreaView` re-renders only when the title bar inset changes, a surface gets a new size at most every 50 ms during a live resize (the last size always arrives), events such as `onLayout` render at default priority instead of synchronously, and `windowResize` and `windowMove` fire only for what changed.
- LogBox is drawn above the app's portals, so it no longer overlaps an error screen the app shows in a modal.
- A view moved by a transform, such as a panel being swiped in or a sheet sliding up, draws its content correctly: clips move with the view, single-line text and icons are no longer hidden behind their own background, and the view no longer jumps for a frame while it moves.
- Builds against gpui-fast `9087620`, which is Longbridge's gpui-fast `main` merged in (upstream's public API for `ContentMask`, `Hitbox` and `paint_svg`, GPUI Kit 0.9.1), plus a rule that a character a focused text input takes is not offered to the key listeners of its ancestors, and `test-support` methods that drive the focused input handler as an input method would. A text input tracks focus on its own element so its own key handlers still see typed characters.
- Builds against gpui-fast `5392403`, which lets an automated run on macOS ask for a window scale factor (`RN_GPUI_TEST_SCALE_FACTOR`) and keeps windows active while the test driver runs the app in the background, so focus and blur work without activating the app.
- Builds against gpui-fast `3a4aada`: a view with rounded corners and overflow hidden clips its content correctly while it is scaled or moved by a transform, and text on macOS is rasterised with Skia's coverage curve instead of Core Graphics' font smoothing, so it carries the same weight as in Chromium (total ink within about 1%).
- Builds against gpui-fast `ac7018a`: content painted into a scroll layer keeps its transforms, so rows no longer stack on each other now and then, and a frame allocates far less, since retained views stop allocating placeholders and empty lists and the tab order is sorted only when focus moves by keyboard. With the allocation cuts below, scrolling a long list in a large app went from about 27.7 million allocations and 11.4 GB allocated to 13.9 million and 5.7 GB.
- A C++ TurboModule is created once per runtime and handed out again on each lookup, as on iOS and Android. Each lookup built a new instance, and a module whose instances share state lost it when an extra one was destroyed: `react-native-quick-sqlite` closed every open database that way, so an app could hang opening its database in a release build. Needs a prebuilt runtime built with the change.
- A source build (`RN_GPUI_BUILD_FROM_SOURCE=1`) of an app whose native modules include C sources, such as `react-native-quick-sqlite`'s `sqlite3.c`, no longer fails with "invalid argument '-std=c++20' not allowed with 'C'". React Native's flag list hands `-std=c++20` to every target that links one of its own; it now applies to C++ sources only.
- A list scrolled fast with the mouse wheel or the scroll bar no longer stays blank until it moves again. React Native held scroll and pointer events until its next event beat, which nothing else might tick, and a list ignored the offsets that arrived while it adjusted for rows above it changing size; events now go out at once, and the offset a wheel or scroll bar stops at is reported once more after it rests.
- An app built before the prebuilt pin changes links the newly pinned runtime instead of the previous one. CMake kept the runtime directory it found first in the build tree's cache, so the app linked the old runtime while the build log named the new one.
- Fewer allocations while drawing: a component renderer gets its node's subtree only when it reads it (`ComponentRenderer::reads_children`), mount observers get a node without its subtree, a node's pointer listeners are built once rather than on every render and registered without copying, a node without a component renderer finds its frame without snapshotting itself, and a node without a filter no longer parses one.

## 0.87.0-alpha.1 - 2026-11-05

- Scrolling a list or `ScrollView` in a window the app decorates itself on Linux (a title bar with caption buttons) is composited from cached tiles again. The window is transparent for its shadow, and the scroll layer refused to cache content over a transparent window even where an opaque panel covered it, so every row was rebuilt on every frame.
- Images decode at the size they are shown and keep only their encoded bytes, so a screen of large photos no longer holds every full-size bitmap (a grid of 24 photos of 4000 x 3000 went from about 3 GB to 0.6 GB on macOS). `Image` is sized from its layout frame.
- Less GPU memory: path textures cover only the area the frame's paths need and are released when idle (about 82 MB for a 2560 x 1600 window down to 0 to 1.3 MB without large paths), instance buffers shrink after a long stretch of low use, windows on one Metal or DirectX device share their glyph atlas and compiled pipelines, and the scroll layer cache follows the window's size (16 to 64 MB).
- A rounded `overflow: 'hidden'` clip inside an effect group no longer crashes the app when the frame is replayed.
- On Windows colour glyphs (emoji) are composited on the CPU, which removes a GPU readback from rasterizing each one.
- On Linux the GPU adapter the compositor or `ZED_DEVICE_ID` names is opened first and the others are not enumerated unless it fails, which shortens startup (about 115 ms to 94 ms to the first frame on an Intel machine).
- A node the pointer came from stops being hovered when the pointer moves onto a native view (`onHoverOut` and the leave events fire). The native view took the pointer without telling the nodes under it, so the node stayed hovered.
- Reloading the app while the window resizes a surface no longer crashes. The reload thread removed the surface manager for a moment, and a resize from the UI thread in that gap (such as the title bar measuring where the menu bar goes) dereferenced it; the size is now kept and applied when the surface restarts.
- `Linking.canOpenURL` on Linux answers `true` for `http` and `https` where no default browser is registered but `$BROWSER` or `x-www-browser` is set, which is what `xdg-open` falls back to when it opens the address.
- Builds against gpui-fast `9e455ae`, which brings in longbridge/gpui-fast and zed `decd2399b1`. It needs Rust 1.98 or newer, so CI and the setup docs use 1.98.1 now. The host keeps its effect groups, colour filters and transforms.
- On Linux a window with a `'none'` title bar and a `'transparent'` or `'blurred'` background, opened with no `x` and `y`, is centred and closes when it loses focus, such as on Alt+Tab or a click elsewhere. On X11 it is kept out of the taskbar and the pager. Wayland ignores the position the app asks for, so it opened in the top-left corner on GNOME 46; the window is now drawn in the middle of a click-through window over the work area, on the monitor the compositor chooses, and `getState()` reports that window's size.
- On Wayland a click outside a tray popover goes to the window or desktop under the overlay. The overlay took it before and closed the popover with it, so the app behind needed a second click. Only the popover's own area takes input now, and the popover closes when it loses focus.
- On X11 a window with a `'none'` title bar no longer keeps the window manager's title bar when the window manager cannot leave the decorations to the app (Openbox, and any without `_GTK_FRAME_EXTENTS`). The frame is removed with the Motif hint, so a palette is frameless there, and translucent with a compositing manager.
- On X11 a window opened with `DesktopWindow.open` is placed at the position asked for, or centred, instead of wherever the window manager puts it (Openbox opened it in the top-left corner).
- On X11 a tray popover whose frame margin is given back is placed by its content, so it opens where the icon puts it and not a margin up and to the left.
- The app no longer panics at startup on a Wayland compositor that settles a window's decorations after it opens (sway). The title-bar inset changed inside the window-bounds observer and refreshed the surface while the root view was borrowed (`cannot read SurfaceRootView while it is already being updated`); the refresh now runs after the observer returns.
- Global shortcuts work on Wayland. They are bound through the desktop's `GlobalShortcuts` portal, which the user allows once, and a press arrives as the portal's `Activated` signal. They used to register through XWayland, which succeeded and never fired. `Shortcuts.onFailure` now also reports a refusal that arrives later, such as the user declining, and a desktop with no portal. The portal knows an app by an installed `<identifier>.desktop` file, which the app writes into `~/.local/share/applications` when there is none.
- `DesktopWindow.open` with `alwaysOnTop` or `visibleOnAllWorkspaces` no longer rejects where the platform cannot do it. On Wayland it failed with `the session is not X11` and the window was left in a half-opened state; the window now opens and the request is skipped, with a warning in the log.
- On Linux a window with a see-through `background`, `shadow: false` or a `'none'` title bar gets no frame. The frame's shadow was painted under the window's content, so a translucent palette showed over a dark block.
- `TrayConfig::popover_anchor_name` sets the popover corner from text, which is how `tray.popoverAnchor` in `desktop.json` reaches it.
- `Tray.showPopover()`, `Tray.hidePopover()` and `Tray.togglePopover()` open and close the tray's popover from code, for example from an item of the tray's menu, and `Tray.setPopoverPosition({anchor, offset})` changes where it opens next time.
- A tray popover on Linux with Wayland opens at the end of the panel's edge instead of in the middle of the screen. The panel is found from the screen's work area, which XWayland publishes as `_NET_WORKAREA`, and the popover is drawn inside a transparent window that covers it; a press outside the popover closes it. `Tray.install` takes `popoverAnchor` and `popoverOffset` to choose the corner, and `RN_GPUI_TRAY_POPOVER_ANCHOR` and `RN_GPUI_TRAY_POPOVER_OFFSET` override them. A panel that reports the click position (KDE on a click, GNOME on a double-click) puts the popover centred on the icon, whether it reports points or device pixels, which differ at a display scale above 1. The work area is read the same way, since GNOME's XWayland reports it in device pixels and KDE's in points. On X11 the popover now also stays inside the work area.
- A tray popover on Linux is drawn with the same measured frame as other windows, rounded and with a shadow, and its content has the size you asked for: the window is grown by the frame's margin. On GNOME, where the compositor places the window, it still closes when it loses focus.
- A window with no menu bar no longer reserves room for one on Linux. A secondary window or a popover lost the menu bar's 26 points of height, and pointer positions in it were offset by them.
- On Linux the first `capabilities()` call waits until the window has reported whether the compositor gave it client-side decorations. `TitleBar` used to read the answer while the window was still opening, took the guess, and drew caption buttons next to the title bar KWin draws. The change is also sent to the app as `gpuiDesktop:windowDecorations`, and the new `useClientDecorations()` hook, exported from `@react-native-gpui/core/desktop`, follows it.

- The Linux window frame's shadow is fitted to the toolkit's measured shadow (opacity, blur, spread and downward offset) instead of one symmetric blur, and its blur no longer ends in a visible step at the edge of the margin.

The corner radius, shadow and border are measured by rendering a window frame off-screen with GTK 4 and libadwaita, GTK 4 alone, or GTK 3, whichever is installed, in a short-lived child process, and cached until the theme, colour scheme, library versions or runtime change. `window.cornerRadius` in `desktop.json` is the radius used where nothing can be measured, `window.shadow: false` removes the shadow and margin, and `RN_GPUI_FRAME_PROBE=off` skips the measurement.
